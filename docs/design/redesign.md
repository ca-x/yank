# Yank 0.2 设计与同步契约

本版替换未上线的旧客户端、数据库和协议；不迁移旧数据。客户端使用固定 commit 的 Rust NSH 0.5.0，管理页使用独立 Web 界面。自有同步包含本版；微信输入法适配不包含。Ditto 通过可选 rutis 插件适配。

## 使用模型

离线记录、搜索、编辑、收藏、收藏板、智能列表、顺序复制、导入和备份不依赖账号或服务器。设备互通必须首次双方确认；设备信任与账号关联分别保存。登录不会开启服务端存储；选择“不关联账号”立即取消本机账号与上传权限。账号邀请只有服务器地址和用户名提示，不携带令牌，对方自行登录。

服务端有三项职责：账号范围内的设备发现、临时加密包中继、用户明确启用后的持久存储。访客只能按精确设备码查询，不能枚举访客或其他账号设备。LAN 公告不建立信任。中继不保存剪贴板历史，端点使用 Iroh/QUIC 验证设备公钥；管理页只能看到已上传到账号存储的数据。

默认选中中继。已配置中继时关闭 IP transport，避免悄悄变成直连。仅直连模式不使用中继。自动模式允许 IP、NAT 穿透和中继回退。未配置服务器/中继时允许局域网直连，仍须配对确认；完全离线时本地功能继续可用。连接状态来自实际选中的 Iroh path。

## 数据与时序（DDIA 审核结果）

每个设备、每个服务端账号都有独立 SQLite WAL 数据库；开启外键和 3 秒 busy timeout。身份为 UUID，内容哈希只用于重复内容识别和 blob 去重。二进制格式原始字节存入 `blobs`；列表只取元数据，详情、复制、导出和同步再恢复 payload。数据目录在 Unix 上为 0700，账号令牌不进入导出。

离线设备都能写，采用版本向量检测因果顺序。每次本地修改产生新的稳定 `version_id` 并递增本设备计数，同时分配不可变的 Lamport `write_order` 与 `write_actor`；新写入标签必须大于本机已观察到的全部标签。落后版本不覆盖新版本；并发版本按 Lamport 标签、actor 与稳定内容键选出一致结果，另一个版本保留在 conflicts。恢复冲突产生新版本。合并后的向量只表示已见上下文，不改写载荷标签，也不参与胜负排序；因果后继的标签必定高于祖先，避免旧载荷在多副本不同到达顺序下重新获胜。墙上时间仅用于显示和历史保留，不用于同步顺序。

`clips` 是当前状态，`changes` 是事务内递增的不可变变更日志。所有写事务使用 BEGIN IMMEDIATE；局部修改先取写锁，再读取/修改当前记录，与 outbox 原子提交。ack 只删除匹配 operation，旧 ack 不能抹掉较新的修改。服务端去重记录 operation 和请求指纹，重试有一个效果，复用 operation 发送不同内容会失败。导入备份在一个事务中写入全部记录与智能列表；失败全部回滚。

游标是最后实际返回的日志 seq，禁止用当前时间跳页。页应用与接收游标提交原子化；epoch 改变即重新播放。发送到服务端使用按 URL、账号和服务端 epoch 隔离的独立发送游标，因此历史记录、已确认记录、从其他设备接收的记录都可上传到新账号或重建后的服务器。账号授权使用代次：关闭上传、解除账号、切换服务器都会使旧任务失效；每个 await 后提交 ack、游标和下载页前，必须持同一授权锁检查 URL、账号、令牌和代次。已经发出的服务器请求可能完成，但旧响应不再改变本机状态。设备授权使用独立代次和取消通知，发送任务、配对意图、接收提交和 OS 剪贴板消费都复核来源授权。

首次历史播放不会改写系统剪贴板。完成设备初次播放后，只有实际合并成功的内容变更才按 `apply_remote` 设置更新桌面系统剪贴板；重复页、删除、只改收藏等元数据不会重复写回。服务端存储拉取只恢复历史，不写系统剪贴板。安卓遵守系统限制，只在前台由用户复制。远端文件记录仅含路径时不得将路径作为本机文件写回，避免误用本机同名文件；本版不传输文件实体。

tombstone、旧日志、去重 operation 暂不回收。图片 blob 去重减少重复体积，但长期数据库仍会增长；安全压缩需要带 epoch 的快照和副本确认策略，不能直接删墓碑或 cursor 之前的数据。自动备份为一致的导出，不复制活动 WAL 文件；保留最近七天。数据库缺失而存在备份时先询问恢复，暂缓自动采集与新备份。

## 二进制协议

唯一协议源为 `proto/yank/v1/yank.proto`，Buf v2 管理、STANDARD lint，`protoc-gen-prost` 0.5.0 生成 Prost 0.14 类型。设备与服务端、设备之间均使用 Protobuf Envelope，包含 protocol_version 和 message kind。HTTP 使用 `application/x-yank`；peer 使用专有 ALPN `yank/clipboard/2`。管理页 JSON 是独立的人机管理接口。

消息最大 16 MiB，记录连同元数据最大 8 MiB。接收 HTTP/QUIC 在解码前限制字节数；分页按编码大小限制，不能因为大图片跳过记录。格式字节直接作为 Protobuf bytes，不套 JSON/base64。当前没有大 blob 分块续传，不把该能力描述为已完成。未知或非法版本/类型/缺失字段必须失败。

## 账号与管理

`YANK_ADMIN_USERNAME`、`YANK_ADMIN_PASSWORD` 仅在用户表为空时创建首个管理员。Argon2 存储密码哈希，随机令牌只持久化哈希，默认 30 天失效。Web 使用 HttpOnly/SameSite=Strict cookie，可配置 Secure；native 用 bearer。改密校验旧密码，管理员可重置其他账号；密码更新与全部会话撤销为一个事务。退出只撤销当前会话。按 IP 的限流共用于登录和密码敏感操作。

服务端存储由服务端读取处理，不能宣称对服务端端到端加密；公网部署应使用 HTTPS。设备中继的内容则由端点加密，服务端不解密。

## UI 与验收

使用语义化浅深色 tokens、应用自有控件、清晰可见的焦点/选中/禁用/等待状态；移动触控目标不少于 48pt。窄桌面与手机用单栏详情，宽桌面用侧栏；未保存草稿按条目保留。高频搜索、选择、复制立即响应，不添加装饰性动画；偶发 Web 登录过渡尊重 reduced-motion。Markdown 图片不自动联网，剪贴板 HTML 不作为网页执行。

发布证据分别记录 Rust 测试、真实 TCP/QUIC、浏览器、Linux 原生窗口和 Android 模拟器，不把 headless 文案测试当成平台验收。完整功能差距见 capability matrix 和 release notes。先验证新版本产物，再删除旧 tag/release。
